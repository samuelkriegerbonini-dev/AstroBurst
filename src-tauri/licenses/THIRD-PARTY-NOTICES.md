# Third-party notices

AstroBurst ships this folder with the desktop bundles and the Linux release tarball. Each row names a third-party work that AstroBurst ports or links, the version in use, its licence, its home page and the licence files in this folder. Where a crate offers a choice of licences, every licence text the crate ships is included.

Scope: the ported works, the star catalogue every installer bundles, the sample data, the system libraries inside the Linux AppImage, and the crates and npm packages below that need a note of their own (bundled C sources, a prebuilt Microsoft library, extra notice files, a package that ships no licence file, build helpers in the frontend bundle). The complete lists sit next to this file: `src-tauri/licenses/THIRD-PARTY-LICENSES-RUST.md` names the Rust standard library, at the `rustc` release the list was generated with, and every crate in `src-tauri/Cargo.lock` with its licence, the release builds that link it, its copyright lines and the licence texts it ships, and `src-tauri/licenses/THIRD-PARTY-LICENSES-NPM.md` does the same for the production npm dependencies of `package.json` and everything they depend on, a superset of the packages whose code reaches the frontend bundle. Both are generated by `node scripts/third-party-licenses/generate.js`; run it again after any change to `Cargo.lock` or `pnpm-lock.yaml`.

Crate rows match `src-tauri/Cargo.lock`; `src/__tests__/thirdPartyNotices.test.ts` fails when a crate row or the vite row is not at its locked version, a crate in the fitsio-pure tree has no row, a row names a file missing from this folder, a file here has no row, a data file that the bundle ships from `src-tauri/resources/` or a sample set the app downloads has no Data row, the release workflow does not put the copyright files of the AppImage's Ubuntu packages into the AppImage, a repository path named here does not exist, the AppImage has no row with the LGPL-2.1 text, no written offer by the maintainer for the source code of its LGPL libraries or no way to identify their versions once the build log is gone, the Rust standard library has no entry or has one at another release than the exact one the release workflow pins, a sentence here or in the Rust list says that entry follows the release toolchain while the workflow pins no exact release, a generated list prints a licence text twice, or a crate of `src-tauri/Cargo.lock` or a production npm package has no entry with a copyright cell and a licence text in the generated lists.

Written offer for the source code of the AppImage libraries. For each AstroBurst release that includes a Linux AppImage, for as long as that AppImage is offered for download and for at least three years after the last day it is offered, Samuel Krieger Bonini, the AstroBurst maintainer, will give anyone who asks, free of charge, the complete corresponding source code, in machine-readable form, of every library that AppImage carries under any version of the GNU Lesser General Public License: WebKitGTK, GTK 3 and libsoup 3, and any other LGPL library that linuxdeploy bundles with them (GLib, Pango, ATK, gdk-pixbuf or cairo, for example, when present), in the exact versions that AppImage contains. To ask, open an issue at https://github.com/samuelkriegerbonini-dev/AstroBurst/issues and name the AstroBurst version; the source is then provided as a download.

How the libraries and their versions are identified. From 0.7.5, `licenses/appimage-libraries/README.md` inside the AppImage names the package and version of every library it carries, as installed on the build machine. `.github/workflows/release.yml` builds the AppImage on the GitHub-hosted `ubuntu-22.04` runner, so every bundled library is a file of an Ubuntu 22.04 LTS (jammy) package installed on that machine on the day the release was built, either by the workflow's `apt-get install` step or with the runner image. `./AstroBurst_<version>_amd64.AppImage --appimage-extract` lists the libraries a given AppImage carries (under `squashfs-root/usr/lib`), and `dpkg -S` on Ubuntu 22.04 names the binary and source package of each. The installed version is not always the newest one the archive held on the build date: `apt-get install` keeps the runner image's own copy of a library whenever it satisfies the new packages, and the build log, which GitHub deletes after 90 days at most, prints only the versions that step installed. The version of each library is therefore read from the file itself: the GNU build ID that `readelf -n` prints for it matches the same file in exactly one build of its binary package, among the versions that the package's publishing history on Launchpad lists for jammy, jammy-updates and jammy-security up to the build date. The source package of that version is what the offer provides.
